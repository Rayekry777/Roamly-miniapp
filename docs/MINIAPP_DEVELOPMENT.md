## 契约职责

本文只管理 `Roamly-miniapp` 消费者体验。HTTP 线协议由后端运行时 OpenAPI 管理，阶段顺序参考 [四端交付路线图](../../Roamly/docs/roadmap/FOUR_END_DELIVERY_ROADMAP.md)。本文不定义数据库、服务端事务、管理员权限、商户审核或商户经营页面。

## 技术与视觉

- 原生微信小程序、TypeScript、TDesign MiniProgram；API、Service、Store、页面与类型分层。
- 视觉真源是当前 `styles/tokens.wxss`、`styles/global.wxss` 和已实现页面。主色 `#ff5f57`，辅助色 `#8275ff`，主文字 `#242331`，辅助文字 `#8f8d99`，页面背景 `#f4f5fb`，内容面 `#ffffff`，边框 `#ececf3`。
- 保持轻盈社区与本地生活风格、大圆角内容面、柔和紫灰阴影和克制动效。竞品截图只参考下单与券信息结构，不复制其颜色、字体、素材或文案。
- 图标优先使用 TDesign 图标；业务 ID 始终为字符串，金额由分格式化，时间以服务端为准。

## 动画约束

- 动画只用于建立层级、表达操作反馈和缓解状态切换，不得承载唯一业务含义，不得延迟跳转、接口请求或服务端状态回查；动画不可用时必须保留相同的文字、图标和页面状态反馈。
- 页面入场统一使用 `320ms ease-out` 的轻微位移与透明度变化，按压反馈统一使用 `160ms ease` 的缩放与透明度变化，成功反馈容器使用 `240ms ease-out`；新增微动效应保持在 `160ms` 至 `320ms`，禁止无业务意义的循环、弹跳、闪烁和大幅位移。
- 优先只改变 `transform` 和 `opacity`，不得通过频繁改变尺寸、位置或阴影造成布局抖动；列表滚动、输入、支付、退款、二维码和倒计时等关键操作不得被装饰动画阻塞。
- Lottie 仅用于登录、签到、发布等离散成功反馈，固定使用 `lottie-miniprogram@1.0.12`、本地受控的动画数据和 Canvas 渲染，`loop` 必须为 `false`，反馈层默认不超过 `1200ms`；不得运行时下载不受控的动画 JSON。
- Lottie 必须服从全局 `motionEnabled` 降级开关；低性能设备停用后直接展示静态成功文案。组件隐藏、重复播放或卸载时必须销毁旧实例，避免并行动画、定时器残留和 Canvas 资源泄漏。
- 动画调整属于视觉契约变更，必须在常见手机宽度和低性能降级路径下验证无布局跳动、重复触发、残影或操作失焦，并由自动化锁定依赖版本、核心时长和非循环配置。

## 客户端协议规则

- 成功响应消费 `Result`、`PageResult`、`CursorPageResult`，204 转换为 `data: null`；错误按真实 HTTP 状态和字符串业务码展示。
- 商品详情消费 `{product,shop}`，订单详情消费 `{order,product,shop}`；不兼容旧字段、旧数字状态或裸对象包装。
- `PENDING_PAYMENT`（待支付）、`PAID`（已支付）、`CANCELED`（已取消）、`REFUNDING`（退款中）、`REFUNDED`（已退款）必须使用中文展示文案。
- 401 清理消费者会话并保留草稿和回跳意图；403、404、409、429、503 保留各自语义，不统一转换成网络错误。
- 空数组展示真实空态；只有响应结构不符合契约时报告“响应格式异常”，不得生成假数据。

## 交易扩展

- 阶段 21 已实现：四类券列表和详情按 `PACKAGE`（套餐券）、`CASH`（代金券）、`DISCOUNT`（折扣券）、`MULTI_USE`（次卡）展示真实权益、价格、有效期、退款规则与销售状态。
- 阶段 22：商品页进入确认订单页，提供数量步进器、门市总价、优惠和实付金额；数量上限使用服务端返回事实。
- 阶段 23：提交订单后进入详情，按 `serverTime` 与 `paymentExpireTime` 展示 15 分钟倒计时；dev/test 点击提交后沿用参考实现弹出“模拟支付成功 / 模拟支付失败 / 暂不支付”三选项，归零后回查服务端状态；WECHAT 参数缺失时显示订单已保存提示，不误报成功。
- 订单页顶部保留参考图的搜索入口，当前页对已加载的真实订单按订单号、商品名和 ID 做本地筛选；“退款/售后”页签由服务端聚合 `REFUNDING` 与 `REFUNDED`。
- 阶段 24：券详情展示退款资格和单券退款入口；退款申请使用固定原因编码、100 字说明和单券数量约束；`REQUESTED`/`PROCESSING` 展示为退款中，次卡首次使用后不展示自助退款。
- 订单详情在待支付、已取消等无券状态仍展示商品摘要；退款中/已退款订单展示退款进度入口，退款中的券冻结券码核销入口。
- 阶段 27：券详情请求 60 秒动态二维码并按剩余时间刷新；二维码不展示裸券 ID，手输编号只作为只读备用信息。
- 所有高风险命令由 API 层生成并发送 `Idempotency-Key`，页面重复点击期间禁用操作。

## 附近商品发现与下单体验（v9）

- 状态：已实现。
- 社区首页保持推荐/关注动态；“附近”直接展示同城在售团购商品，支持门店分类、商品或门店关键词、综合、销量、距离与价格筛选。
- 附近页与商户详情复用同一商品卡；商品详情展示大图、价格权益、有效期、使用规则、唯一适用门店和本店其他商品；购买须知可从详情摘要进入独立页面。
- 未登录购买先完成消费者登录并自动直达确认订单；确认页金额、库存与限购只消费服务端确认快照，任何导航或请求失败都必须提供可见反馈。
- 参考截图只用于信息层级、比例、密度和交互位置对照，不复制第三方素材、品牌、颜色或不存在的配送、多店通用、平台券与营销能力。

## 页面状态

- 每个列表覆盖首次加载、分页加载、真实空态、筛选无结果、失败和重试。
- 每个详情覆盖加载、404、权限失效、状态冲突和刷新后状态变化。
- 倒计时、本地缓存和推送只改善体验，不能自行修改订单、支付、券或退款状态。
- 定位拒绝保留无距离结果；扫码、相机与商户经营异常不属于消费者端页面职责。
