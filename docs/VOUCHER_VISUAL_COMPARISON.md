# Roamly 团购券页面对照记录

## 当前验证

- `npm run verify`：37 个测试文件、142 个测试通过。
- `npm run build:npm`：通过。
- 2026-09-06 已在微信开发者工具 iPhone 15 Pro 模拟器中实际复核首页团购入口、商品详情、确认订单（含限购错误态）和附近团购流；其余支付结果、券包、退款和账单页已通过页面契约与状态测试，Android/iOS 真机截图仍未确认。

## 本轮页面重构记录

- `package-order/pages/result` 按“状态图标 → 门店/订单入口 → 券码票据卡 → 操作按钮”重排；成功态收敛为购买成功主路径，失败/暂不支付/渠道不可用时再显示金额和订单保留说明，不显示参考应用的银行卡、奖励、广告和红包模块。
- `package-order/pages/detail` 按“待到店使用/退款中 → 使用限制 → 门店操作 → 商品券卡 → 券码状态 → 原订单”重排；有效期使用商品返回的 `validEndTime`/`validityText`，不再把支付截止时间当消费截止时间。
- `package-voucher/pages/wallet` 的券码弹窗保留条形码、动态二维码、券码和倒计时；未使用和部分使用的次卡可继续核销，退款中仅展示“券码已冻结”，已使用/已过期/已退款券不提供二维码；从后台回到前台时重新申请服务端动态 token，生成失败时提供“重新生成”入口。
- `package-shop/pages/list` 在商品过滤场景只显示真实适用门店，隐藏无关的分类和排序入口，并增加城市/地点搜索层级；商品详情的适用门店入口会携带 `productId`。
- `package-order/pages/list` 按参考图补齐订单搜索、状态页签、订单号和分状态操作；优先显示服务端商品封面，没有封面时使用明确的团购券占位，不伪造商品图片。
- `package-order/pages/refund` 和 `package-order/pages/refund-detail` 对齐退款数量、金额、原因弹窗、原支付渠道、退款进度和退款单号分组。
- 订单列表顶部改为真实搜索控件，按当前已加载订单的订单号、商品名和 ID 过滤；没有后端关键词能力时不伪造远程搜索结果。
- 商品详情价格摘要统一只显示当前售价；购买须知的有效期、使用时间、使用规则和不可用日期使用统一图标行。
- 消费者订单的“退款/售后”页签聚合退款中与已退款订单，和参考图的单一售后入口保持一致；管理端仍按精确状态查询。
- `pages/me` 用真实支持的订单、券包和动态入口组成四宫格，删除参考应用的签到、最近浏览、钱包、草稿箱、达人中心等不兼容入口。
- `pages/home` 增加真实“团购精选”横向入口，点击直接进入团购详情；`pages/nearby` 保留完整的城市/团购/附近层级、胶囊搜索、真实分类筛选和无卡片边框商品流。主色仍使用 Roamly 红珊瑚色，不复制参考应用橙色。
- `package-voucher/pages/product` 将首屏改为大图叠加价格摘要卡，并把套餐明细、自助核销、购买须知、适用门店和本店团购按参考图顺序排列。
- `components/shop-card` 补齐真实门店封面、评分和定位操作；无封面或无坐标时分别显示空封面和隐藏无效操作。
- Mock 支付保留参考项目的 `wx.showActionSheet` 三选项：模拟支付成功、模拟支付失败、暂不支付；支付渠道不可用时不会弹出假支付选项。
- `tests/payment-flow.test.ts` 锁定三选项文案、成功/失败场景和“暂不支付不调用支付接口”的行为。
- 确认订单遇到限购、库存不足或下架时，使用独立红色提示卡显示服务端原因和“重新确认”，提交栏回落为不可提交状态，贴近参考图的异常流程。
- 模拟器复核发现首页团购横卡原先把原生 `data-id` 当作自定义事件 `detail.id` 读取，已改为读取 `currentTarget.dataset.id`；同时为团购列表补充稳定原始 key，清除 WXML 嵌套 key 和对象 key 警告。
- 本轮逐图校准了确认订单的“商品/金额/支付方式/固定提交栏”分层；支付方式区域明确提示提交后的三选项，而不是把支付入口混在金额明细中。
- 适用门店页改为参考图的无大图行式布局，保留评分、地址、营业时间和真实导航能力；商品过滤时隐藏无关分类与排序。
- 商品购买须知补充服务端返回的不可用日期，避免只展示有效期而遗漏参考图中的限制信息。
- 商品详情的“购买须知”摘要现在进入独立 `package-voucher/pages/notice` 页面，按参考图拆分有效期、使用时间、使用规则和价格/销量说明，保持轻量并继续复用真实商品契约。
- 到店使用状态保留“查看券码/动态二维码”入口；退款中的券仅展示券码和处理状态，不再提供核销二维码，避免退款处理中继续消费；订单详情的“再来一单”与已支付、退款中和已退款状态保持一致。
- 订单详情补齐待支付/已取消状态的商品摘要，退款中和已退款状态提供退款账单入口；订单结果票据在多份券时显示实际券数，商品封面优先使用后端受控媒体路径。
