## 文档定位

本文保存 `Roamly-miniapp` 已落地的消费者体验、页面状态、接口消费和验证要求，不记录开发阶段或路线图。HTTP 接口以后端运行时 OpenAPI 为准，退款和客服规则见后端[退款客服与资金结算业务细节](../../Roamly/docs/project-details/退款客服与资金结算业务细节.md)。

## 技术与视觉

- 原生微信小程序、TypeScript、TDesign MiniProgram；API、Service、Store、页面与类型分层。
- 视觉真源是当前 `styles/tokens.wxss`、`styles/global.wxss` 和已实现页面。主色 `#ff5f57`，辅助色 `#8275ff`，主文字 `#242331`，辅助文字 `#8f8d99`，页面背景 `#f4f5fb`，内容面 `#ffffff`，边框 `#ececf3`。
- 保持轻盈社区与本地生活风格、大圆角内容面、柔和紫灰阴影和克制动效。竞品截图只参考下单与券信息结构，不复制其颜色、字体、素材或文案。
- 图标优先使用 TDesign 图标；业务 ID 始终为字符串，金额由分格式化，时间以服务端为准。

## 动画约束

- 动画只用于建立层级、表达操作反馈和缓解状态切换，不得承载唯一业务含义，不得延迟跳转、接口请求或服务端状态回查；动画不可用时必须保留相同的文字、图标和页面状态反馈。
- 页面入场统一使用 `320ms ease-out` 的轻微位移与透明度变化，按压反馈统一使用 `160ms ease` 的缩放与透明度变化，成功反馈容器使用 `240ms ease-out`；新增微动效应保持在 `160ms` 至 `320ms`，禁止无业务意义的循环、弹跳、闪烁和大幅位移。
- 优先只改变 `transform` 和 `opacity`，不得通过频繁改变尺寸、位置或阴影造成布局抖动；列表滚动、输入、支付、退款、二维码和倒计时等关键操作不得被装饰动画阻塞。
- Lottie 仅用于登录、签到、发布等离散成功反馈，固定使用 `lottie-miniprogram@1.0.12`、本地受控的动画数据和 Canvas 渲染，`loop` 必须为 `false`，反馈层默认不超过 `1200ms`；不得运行时下载不受控的动画 JSON。
- Lottie 必须服从全局 `motionEnabled` 降级开关；低性能设备停用后直接展示静态成功文案。组件隐藏、重复播放或卸载时必须销毁旧实例，避免并行动画、定时器残留和 Canvas 资源泄漏。
- 动画调整属于视觉契约变更，必须在常见手机宽度和低性能降级路径下验证无布局跳动、重复触发、残影或操作失焦，并由自动化锁定依赖版本、核心时长和非循环配置。

## 客户端协议规则

- 成功响应消费 `Result`、`PageResult`、`CursorPageResult`，204 转换为 `data: null`；错误按真实 HTTP 状态和字符串业务码展示。
- 商品详情消费 `{product,shop}`，订单详情消费 `{order,product,shop}`；不兼容旧字段、旧数字状态或裸对象包装。
- `PENDING_PAYMENT`（待支付）、`PAID`（已支付）、`CANCELED`（已取消）、`REFUNDING`（退款中）、`REFUNDED`（已退款）必须使用中文展示文案。
- 401 清理消费者会话并保留草稿和回跳意图；403、404、409、429、503 保留各自语义，不统一转换成网络错误。
- 空数组展示真实空态；只有响应结构不符合契约时报告“响应格式异常”，不得生成假数据。

## 城市切换与定位模式

- 城市状态分为 `REAL_LOCATION`、`MANUAL_CITY` 和 `DEFAULT_CITY`。首次进入或定位失败时使用杭州（`330100`）作为默认城市，定位失败不阻塞首页浏览。
- `REAL_LOCATION` 保存微信真实经纬度、城市和区县；首页推荐动态由服务端根据真实坐标解析城市+区县后过滤。只有该模式支持距离排序。
- `MANUAL_CITY` 由用户主动切换产生，持久化保存至本地；请求只携带所选城市，不携带经纬度或区县，重新进入页面不会自动覆盖用户选择。
- `DEFAULT_CITY` 和 `MANUAL_CITY` 下，首页推荐、门店、商品、关键词搜索和点评均按城市隔离；门店和商品不做区县硬过滤。点击距离排序时提示先恢复定位，不自动请求定位。
- “恢复定位”是唯一从手动/默认城市重新请求微信定位的发现入口。用户拒绝授权、超时或设备失败时保留可浏览的城市状态，并提供设置/重试入口；定位请求迟到时不得覆盖用户刚选择的城市。

## 消费者账号与个人资料

- 登录页默认验证码登录；验证码下方左侧注册、右侧密码登录，三种模式原地切换。
- 注册使用 `/v1/auth/registrations`，必须设置 8–64 位且同时含字母和数字的密码；验证码登录只允许已有账号。
- “我的”进入个人信息页，仅展示头像、昵称、手机号、密码、性别和生日；昵称按北京时间自然日每天最多修改一次，性别和生日在选择器确认后自动保存，退出登录入口位于个人信息页底部。
- 公开用户主页由内容流头像进入，直接消费 `/v1/users/{userId}/profile`，仅展示头像、昵称、性别、关注/粉丝/动态数，不展示手机号、生日或城市。
- 手机号换绑和密码修改成功后清理本地会话并回到登录页；头像上传使用 `USER_AVATAR` 用途并在微信原生 `1:1` 裁剪后保存，动态和点评分别使用 `POST`、`SHOP_REVIEW` 用途；上传失败会清理临时媒体，城市切换以 best-effort 同步内部偏好。

## 交易扩展

- 四类券列表和详情按 `PACKAGE`（套餐券）、`CASH`（代金券）、`DISCOUNT`（折扣券）、`MULTI_USE`（次卡）展示真实权益、价格、有效期、退款规则与销售状态。
- 商品页进入确认订单页，提供数量步进器、门市总价、优惠和实付金额；数量上限使用服务端返回事实。
- 提交订单后进入详情，按 `serverTime` 与 `paymentExpireTime` 展示 15 分钟倒计时；dev/test 点击提交后沿用参考实现弹出“模拟支付成功 / 模拟支付失败 / 暂不支付”三选项，归零后回查服务端状态；WECHAT 参数缺失时显示订单已保存提示，不误报成功。
- 订单页顶部保留参考图的搜索入口，当前页对已加载的真实订单按订单号、商品名和 ID 做本地筛选；“退款/售后”页签由服务端聚合 `REFUNDING` 与 `REFUNDED`。
- 券详情展示退款资格和单券退款入口；退款申请使用固定原因编码、100 字说明和单券数量约束；`REQUESTED`/`PROCESSING` 展示为退款中，次卡首次使用后不展示自助退款。
- 订单详情在待支付、已取消等无券状态仍展示商品摘要；退款中/已退款订单展示退款进度入口，退款中的券冻结券码核销入口。
- 券详情请求二维码并按服务端有效期刷新；二维码不展示裸券 ID，手输编号只作为只读备用信息。
- 所有高风险命令由 API 层生成并发送 `Idempotency-Key`，页面重复点击期间禁用操作。

## 附近店铺发现与下单体验

- 状态：已实现。
- 社区首页保持推荐/关注动态；“附近”仅展示美食、休闲娱乐两个入口，分类页支持二级分类、店铺或可售券关键词、综合推荐、销量、距离与评分排序。
- 分类页使用店铺卡片聚合最多两张可售券；店铺详情展示全部可售券。券详情保留大图、价格权益、有效期、使用规则、唯一适用门店和本店其他商品；购买须知可从详情摘要进入独立页面。
- 未登录购买先完成消费者登录并自动直达确认订单；确认页金额、库存与限购只消费服务端确认快照，任何导航或请求失败都必须提供可见反馈。
- 参考截图只用于信息层级、比例、密度和交互位置对照，不复制第三方素材、品牌、颜色或不存在的配送、多店通用、平台券与营销能力。

## 页面状态

- 每个列表覆盖首次加载、分页加载、真实空态、筛选无结果、失败和重试。
- 每个详情覆盖加载、404、权限失效、状态冲突和刷新后状态变化。
- 倒计时、本地缓存和推送只改善体验，不能自行修改订单、支付、券或退款状态。
- 定位拒绝保留无距离结果；扫码、相机与商户经营异常不属于消费者端页面职责。

## 平台客服与退款时间线

- “我的”提供平台客服工单列表、创建和会话入口；订单详情与退款详情可以携带订单、券或退款 ID 创建关联工单。
- 工单会话支持游标加载、图片附件、未读数量、关闭和重新打开；消费者只能读取本人工单及公开消息，不能看到内部备注。
- 退款详情直接展示 `decisionStatus`、`executionStatus`、Mock 渠道结果、失败原因、逐券金额和服务端时间线；订单页主动查询退款记录，不再仅根据订单交易状态推断退款进度。
- WebSocket 或页面重连只触发重新查询，不能将退款或客服工单改为“处理中”。

## 店铺发现重构（2026-09-13）

附近页只包含美食和休闲娱乐入口；社区首页保持推荐、关注与动态。分类页路由为 `/package-shop/pages/list/index?categoryId=1|2`，统一搜索、二级分类、综合/距离/销量/评分筛选和店铺卡片。定位和城市切换只在首页操作，分类页不显示城市切换、恢复定位或城市弹窗，沿用首页位置；没有真实定位时距离排序提示返回首页开启定位。

分类页从 `/v1/shops/discovery` 读取按店铺分页的结果，有券最多展示热销和低价两张；券行直接进详情，店铺主体查看全部优惠，无券店铺保留。分类目录从 `/v1/shop-types/tree` 读取。

两个分类保存独立浏览状态，真实坐标参与地域解析；切换城市和坐标后失效重载。购买返回刷新已浏览列表；适用门店继续通过 productId 限定真实归属。旧全站商品流 API、排序类型和调用已移除。

## 确认订单活动优惠（2026-09-13）

独立确认页和券详情购买弹层统一显示“活动优惠”合计，展开分别显示商家补贴、平台补贴；金额来自订单确认接口，已经按购买数量汇总。金额为零的明细不显示，全部为零显示“暂无活动优惠”，接口尚未返回时显示“待确认”。小计与提交栏继续使用后端实付金额，不在前端二次扣减。删除未接入业务的“优惠券”占位行及其展开状态；保留团购券商品、券包和交易履约。

## 分类 SVG 图标

附近双入口及14个二级分类按名称映射本地原创 SVG，另有全部图标，共17枚。统一64px画布、圆角线条，暖橙用于美食、紫色用于娱乐、薄荷色用于放松及户外；不同分类使用专属物件。图标由 services/shop.ts 的分类树适配统一绑定，优先精确分类名称，避免旧数据中复用图片地址造成图标重复。分类图片容器背景透明，不影响店铺照片占位。
